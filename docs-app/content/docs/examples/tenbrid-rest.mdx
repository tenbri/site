title: tenbrid over REST
description: "Run tenbrid locally, then write, list, tail and verify entries with curl, Python, TypeScript or gRPC."
---


`tenbrid` serves streams over REST and gRPC, so agents in any language can write to them. You will
start it on your machine with one stream and one bearer token, record an intent and its outcome,
retry a write safely with the same `Idempotency-Key`, list and tail entries, and ask the server to
verify the stream. Every call is shown with `curl` (the REST tab), Python
([httpx](https://www.python-httpx.org/)) and TypeScript (the built-in `fetch`). A gRPC client
closes the page.

**Prerequisites:** the `tenbri` and `tenbrid` binaries ([install](/docs/getting-started/install/)),
and one of:

## 2. Configure and start tenbrid

Each token is bound to one principal; entries written with it carry that principal.

```toml title="tenbrid.toml"
[streams.support]
path = "audit/support"

[[tokens]]
sha256 = "sha256:d7a060573fd59ee31df6395b9d4222475bf18dc67b054533d362c3d1921e39d5"
principal = { kind = "agent", id = "support-assistant" }
```

REST listens on `127.0.0.1:7070` and gRPC on `127.0.0.1:7071` by default. `TENBRI_LISTEN` and
`TENBRI_GRPC_LISTEN` (or `listen` and `grpc_listen` in the file) change them. `TENBRI_KEYS` is
read from the environment, as `tenbri` does.

```sh
TENBRI_LISTEN=127.0.0.1:8080 TENBRI_GRPC_LISTEN=127.0.0.1:8081 tenbrid --config tenbrid.toml
```

```text
tenbrid 0.1.0-beta.5: REST on http://127.0.0.1:8080, gRPC on 127.0.0.1:8081, 1 streams
```

In another terminal, export the token from step 1 and make a client. The Python and TypeScript
snippets on this page form one script: each step continues the previous one.

```sh
export TOKEN=tnbt_c5b3bd4c…   # the token printed in step 1
```

```ts title="client.ts"
import { ulid } from 'ulid'

const base = 'http://127.0.0.1:8080'
const auth = { Authorization: `Bearer ${process.env.TOKEN}` }

console.log(await (await fetch(`${base}/v1/health`)).json())

async function post(path: string, key: string, body: unknown) {
  const r = await fetch(`${base}${path}`, {
    method: 'POST',
    headers: { ...auth, 'Idempotency-Key': key, 'Content-Type': 'application/json' },
    body: JSON.stringify(body),
  })
  return { status: r.status, body: await r.json() }
}
```

## 3. Write an intent

Every write carries an `Idempotency-Key`: the entry id, a ULID your client generates. `kind` and
`phase` come from the route, `principal` from the token, `source` defaults to `sdk` and
`durability` to `local`. The response comes back once the intent is durable, so the action can
run.

Send the same request again (a retry after a timeout, say) and you get the original entry back,
with status 200 and `"replayed":true`, instead of a second entry. A first write answers 201.

<Tabs groupId="lang" persist items={["Python","TypeScript","REST"]}>
<Tab value="Python">

```python title="client.py"
intent_id = str(ULID())  # the Idempotency-Key, which becomes the entry id
draft = {
    "action": {"type": "issue_refund", "target": "stripe:charge/ch_3PqX"},
    "inputs": [{
        "ref": "policy:refund",
        "version": "14",
        "digest": "hmac-sha256:9f2c41aa9f2c41aa9f2c41aa9f2c41aa9f2c41aa9f2c41aa9f2c41aa9f2c41aa",
    }],
}
r = client.post("/v1/streams/support/intents", json=draft, headers={"Idempotency-Key": intent_id})
print(r.status_code, r.json()["entry"]["seq"], r.json()["replayed"])

# A retry with the same key and draft returns the original entry.
r = client.post("/v1/streams/support/intents", json=draft, headers={"Idempotency-Key": intent_id})
print(r.status_code, r.json()["entry"]["seq"], r.json()["replayed"])
```

```text
201 3 False
200 3 True
```

</Tab>

## 5. List entries

`GET /v1/streams/{stream}/entries` filters by `input`, `action`, `principal`, `target`, `subject`
and `after_seq`, with `limit` (default 100, at most 1000). `?action=issue_refund` returns both the
intent and the outcome.

<Tabs groupId="lang" persist items={["Python","TypeScript","REST"]}>
<Tab value="Python">

```python title="client.py"
r = client.get("/v1/streams/support/entries", params={"input": "policy:refund@14"})
for m in r.json()["entries"]:
    print(m["verification"], m["entry"]["seq"], m["entry"]["phase"], m["entry"]["id"])
```

Each match carries the entry's `seq` and `hash`; `as_of` is the head of the stream the answer was
read from. Before answering, `tenbrid` checks each match against the batch in storage that holds
it: if that batch was edited on disk since `tenbrid` started, the request fails with status 500
and `TENBRI_STREAM_BROKEN` instead of returning the entry as `tenbrid` first read it
([Verify as an auditor](/docs/examples/verify-as-an-auditor/) shows it).

## 6. Tail

`/tail` is a server-sent event stream: the entries after `after_seq`, then new ones as they are
written. Each event's `id` is the entry's sequence number, so a client reconnects with
`Last-Event-ID`.

<Tabs groupId="lang" persist items={["Python","TypeScript","REST"]}>
<Tab value="Python">

```python title="client.py"
with client.stream("GET", "/v1/streams/support/tail", params={"after_seq": 2}, timeout=None) as r:
    for line in r.iter_lines():
        if line.startswith("data: "):
            m = json.loads(line.removeprefix("data: "))
            print(m["verification"], m["entry"]["seq"], m["entry"]["phase"])
            if m["entry"]["phase"] == "outcome":
                break  # stop after the first outcome; drop this to follow forever
```

```text
verified 3 intent
verified 4 outcome
```

</Tab>
<Tab value="TypeScript">

```ts title="client.ts"
const tail = await fetch(`${base}/v1/streams/support/tail?after_seq=2`, { headers: auth })
const decoder = new TextDecoder()
let buffer = ''
read: for await (const chunk of tail.body!) {
  buffer += decoder.decode(chunk, { stream: true })
  let nl
  while ((nl = buffer.indexOf('\n')) >= 0) {
    const line = buffer.slice(0, nl)
    buffer = buffer.slice(nl + 1)
    if (!line.startsWith('data: ')) continue
    const m = JSON.parse(line.slice(6))
    console.log(m.verification, m.entry.seq, m.entry.phase)
    if (m.entry.phase === 'outcome') break read // stop after the first outcome; drop this to follow forever
  }
}
```

```text

verified 4 outcome
```

## Over gRPC

The gRPC API has the same operations and error codes as REST. Entries travel as their canonical
JSON (`entry_json`) and drafts as JSON strings (`draft_json`); every call but health checks carries
`authorization: Bearer <token>` metadata. The service is described in
[`tenbri.proto`](https://github.com/tenbri/tenbri/blob/main/contract/proto/tenbri/v1/tenbri.proto);
download it next to your client:

```sh
curl -fLO https://raw.githubusercontent.com/tenbri/tenbri/main/contract/proto/tenbri/v1/tenbri.proto
```

<Tabs groupId="lang" persist items={["Python","TypeScript"]}>
<Tab value="Python">

Generate the stubs with `grpcio-tools`:

```sh
pip install grpcio grpcio-tools python-ulid
python -m grpc_tools.protoc -I. --python_out=. --grpc_python_out=. tenbri.proto
```

```python title="grpc_client.py"
import json
import os

import grpc
from ulid import ULID

import tenbri_pb2 as pb
import tenbri_pb2_grpc

channel = grpc.insecure_channel("127.0.0.1:8081")
api = tenbri_pb2_grpc.TenbriServiceStub(channel)
auth = [("authorization", f"Bearer {os.environ['TOKEN']}")]

intent_id = str(ULID())  # the idempotency key, which becomes the entry id
draft = {"action": {"type": "issue_refund", "target": "stripe:charge/ch_3PqX"}}
r = api.AppendIntent(
    pb.AppendIntentRequest(stream="support", idempotency_key=intent_id, draft_json=json.dumps(draft)),
    metadata=auth,
)
print("intent ", json.loads(r.appended.entry_json)["seq"], "replayed:", r.appended.replayed)

r = api.AppendOutcome(
    pb.AppendOutcomeRequest(
        stream="support",
        idempotency_key=str(ULID()),
        draft_json=json.dumps({"intent": intent_id, "status": "ok"}),
    ),
    metadata=auth,
)
print("outcome", json.loads(r.appended.entry_json)["seq"])

v = api.VerifyStream(pb.VerifyStreamRequest(stream="support"), metadata=auth)
print("broken:" if v.HasField("broken") else "verified", v.entries, "entries, pinned to", v.pinned_key)
```

```text
intent  3 replayed: False
outcome 4
verified 4 entries, pinned to sha256:07c2b3fa9a27514503d4e4f2e2a55001ff86cd0260616b6a10fa26dba37ae65a
```

A wrong token raises `grpc.RpcError` with `StatusCode.UNAUTHENTICATED` and the details
`unknown token`.

<Tab value="TypeScript">

Load the proto at runtime with `@grpc/proto-loader`; no code generation:

```sh
npm install @grpc/grpc-js @grpc/proto-loader ulid
```

```ts title="grpc-client.ts"
import * as grpc from '@grpc/grpc-js'
import * as protoLoader from '@grpc/proto-loader'
import { promisify } from 'node:util'
import { ulid } from 'ulid'

const def = protoLoader.loadSync('tenbri.proto', { defaults: true })
const { tenbri } = grpc.loadPackageDefinition(def) as any
const api = new tenbri.v1.TenbriService('127.0.0.1:8081', grpc.credentials.createInsecure())
const auth = new grpc.Metadata()
auth.set('authorization', `Bearer ${process.env.TOKEN}`)
const call = (method: string, req: object) => promisify(api[method].bind(api))(req, auth) as Promise<any>

const intentId = ulid() // the idempotency key, which becomes the entry id
const draft = { action: { type: 'issue_refund', target: 'stripe:charge/ch_3PqX' } }
let r = await call('AppendIntent', { stream: 'support', idempotencyKey: intentId, draftJson: JSON.stringify(draft) })
console.log('intent ', JSON.parse(r.appended.entryJson).seq, 'replayed:', r.appended.replayed)

r = await call('AppendOutcome', {
  stream: 'support',
  idempotencyKey: ulid(),
  draftJson: JSON.stringify({ intent: intentId, status: 'ok' }),
})
console.log('outcome', JSON.parse(r.appended.entryJson).seq)

const v = await call('VerifyStream', { stream: 'support' })
console.log(v.broken ? 'broken:' : 'verified', Number(v.entries), 'entries, pinned to', v.pinnedKey)
api.close()
```

```text
intent  3 replayed: false
outcome 4
verified 4 entries, pinned to sha256:ddcabc1dfb2d364e97c1285bfbf0933a39852d38293afb9363147b9de991e79d
```

`{ defaults: true }` makes `replayed: false` appear instead of being left out.

</Tab>
</Tabs>

Each gRPC run used a fresh stream, so its seq numbers start at 3.

## What happened

`tenbrid` signed and chained each entry exactly as `tenbri append` does, using the stream's session
key from `TENBRI_KEYS`, and stamped the token's principal on it. The `Idempotency-Key` became the
entry id, which makes retries safe. The stream on disk is a normal stream: `tenbri verify
audit/support --key …` checks it without the server.

<Callout type="idea">
A Python or Node agent on the same machine as the stream can skip the server and write in process
with the `tenbri` package: `tenbri.init()` and `@tenbri.decision` in Python, `init()` and
`decision()` in Node. See [Record a refund](/docs/examples/record-a-refund/).
</Callout>
