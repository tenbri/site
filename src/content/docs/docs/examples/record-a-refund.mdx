A support agent wants to refund a charge, and a person, Alice, approves it first. You will record
three entries: Alice's `approval`, the agent's `intent` that cites the approval by its entry hash
and names the policy and rule it relied on, and the `outcome` once the refund ran. Then you read
them back and verify the stream against its pinned fingerprint. Pick a language once: every tab on
the page follows it.

## Steps

<Steps>

1. **Create the stream, then record the approval, the intent and the outcome.**

   An approval needs a `principal` (the approver) and an `action` (what is approved). The intent
   cites it as `{"by": <approver>, "entry": <entry hash>}`, where the entry hash is SHA-256 of a
   zero byte followed by the stored line (canonical JSON), as `sha256:<hex>`. The intent is
   durable before the refund runs; the outcome closes it by `id`.

   <Tabs syncKey="lang">


   <TabItem label="Python">

   `tenbri.init()` opens the stream, creating it and its keys on first use, and closes it (flushing)
   at exit. `@tenbri.decision` makes each call of a function a decision: the intent is durable
   before the function runs, then the outcome follows: `ok`, `refused` if it raises
   `tenbri.Refused`, `error` for any other exception. `target` is a template of the function's
   arguments, `policy` (`ref@version`) is the rule that allowed it, and `inputs` pins what the agent
   read, with the keyed digest of its content.

   ```python title="refund.py"
   import hashlib
   import json
   import os

   import tenbri


   def entry_hash(entry: dict) -> str:
       """SHA-256 of a zero byte and the stored line (canonical JSON), as sha256:<hex>."""
       line = json.dumps(entry, sort_keys=True, separators=(",", ":"), ensure_ascii=False)
       return "sha256:" + hashlib.sha256(b"\0" + line.encode()).hexdigest()


   # Opens the stream, creating it and its keys on first use; closed (flushed) at exit.
   log = tenbri.init(
       "./audit/support",
       agent="agent:support-assistant",
       digest_key=os.environ["TENBRI_DIGEST_KEY"].encode(),
   )
   print("pin this:", log.fingerprint)

   # 1. Alice approves the refund.
   approval = log.append(
       {
           "kind": "approval",
           "principal": "person:alice",
           "action": {"type": "issue_refund", "target": "stripe:charge/ch_3PqX"},
       }
   )
   print("approval", approval["seq"], entry_hash(approval))


   # 2. The agent's refund. Each call is a decision: the intent is durable before the function
   #    runs, and the outcome (ok, refused or error) is written when it returns or raises.
   @tenbri.decision(
       "issue_refund",
       target="stripe:charge/{charge}",
       policy="rule:refund-under-100@3",
       inputs=[("policy:refund", "14", "refunds under 100 EUR are automatic")],
       approval={"by": approval["principal"], "entry": entry_hash(approval)},
   )
   def issue_refund(charge: str) -> None:
       print("refunding", charge)  # call your payment provider here


   issue_refund("ch_3PqX")
   ```

   <TabItem label="TypeScript">

   `init()` opens the stream, creating it and its keys on first use, and closes it (flushing)
   before the process exits. `decision(options, fn)` makes each call of `fn` a decision: the intent
   is durable before `fn` runs, then the outcome follows: `ok`, `refused` if it throws `Refused`,
   `error` for anything else it throws. `target` is a template of the arguments (`{charge}` reads
   the first argument's `charge`), `policy` (`ref@version`) is the rule that allowed it, and
   `inputs` pins what the agent read, with the keyed digest of its content.

   ```ts title="refund.ts"
   import { createHash } from 'node:crypto'
   import { decision, init, type Entry } from 'tenbri'

   // SHA-256 of a zero byte and the stored line (canonical JSON), as sha256:<hex>.
   function canonical(v: unknown): string {
     if (Array.isArray(v)) return `[${v.map(canonical).join(',')}]`
     if (v !== null && typeof v === 'object') {
       const keys = Object.keys(v).sort()
       return `{${keys.map((k) => `${JSON.stringify(k)}:${canonical((v as Record<string, unknown>)[k])}`).join(',')}}`
     }
     return JSON.stringify(v)
   }
   function entryHash(entry: Entry): string {
     return 'sha256:' + createHash('sha256').update('\0' + canonical(entry)).digest('hex')
   }

   // Opens the stream, creating it and its keys on first use; closed (flushed) before exit.
   const log = await init({
     stream: './audit/support',
     agent: 'agent:support-assistant',
     digestKey: process.env.TENBRI_DIGEST_KEY!,
   })
   console.log('pin this:', log.fingerprint)

   // 1. Alice approves the refund.
   const approval = await log.append({
     kind: 'approval',
     principal: 'person:alice',
     action: { type: 'issue_refund', target: 'stripe:charge/ch_3PqX' },
   })
   console.log('approval', approval.seq, entryHash(approval))

   // 2. The agent's refund. Each call is a decision: the intent is durable before the function
   //    runs, and the outcome (ok, refused or error) is written when it returns or throws.
   const issueRefund = decision(
     {
       action: 'issue_refund',
       target: 'stripe:charge/{charge}',
       policy: 'rule:refund-under-100@3',
       inputs: [{ ref: 'policy:refund', version: '14', content: 'refunds under 100 EUR are automatic' }],
       approval: { by: approval.principal, entry: entryHash(approval) },
     },
     async ({ charge }: { charge: string }) => {
       console.log('refunding', charge) // call your payment provider here
     },
   )

   await issueRefund({ charge: 'ch_3PqX' })
   ```

   In every tab, the intent's `prev` equals the approval's entry hash: the approval is the entry
   just before it, so the hash you computed is the one the chain uses. An `approval.entry` that
   does not name an earlier approval entry is refused with `bad_approval`.

2. **Read the entries back and verify.**

   Pin the fingerprint the stream printed when you created it. Reads then check the stream
   against it, and each match carries its verification status.

   <Tabs syncKey="lang">
   <TabItem label="CLI">

   Without a query index, `query` reads and verifies the whole stream, so each row is
   `verified`. With one (`tenbri index rebuild`), rows are `indexed`: each is checked against the
   batch in storage that holds it, and a batch edited on disk fails the query with exit 1.

   ```sh
   PIN=sha256:4282909ee7474c3eeeb243ba852f77da5b1f10dc68e6a83c4b6b26ada3749123
   tenbri query audit/support --action issue_refund --key $PIN \
     | jq -c '{verification, seq, kind: .entry.kind, phase: .entry.phase, status: .entry.status, approved_by: .entry.approval.by.id}'
   tenbri verify audit/support --key $PIN
   ```

## What happened

You wrote three signed entries that chain to each other. The intent cites the approval by its
entry hash and pins the policy version and rule it relied on, so none of them can be swapped or
edited without breaking verification. The outcome names its intent by `id`, which closes it: an
intent without an outcome is reconciled with `status: unknown` by a later writer after an hour.
