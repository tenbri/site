Two lines turn a function into a recorded decision: `init()` opens a stream, and `decision`
wraps the function that acts. Each call writes a signed **intent** before the function runs and
an **outcome** after it: `ok`, `refused` or `error`. Then the `tenbri` CLI tails the stream and
verifies it against its pinned key. Install the package you pick, and the CLI to check the result
([Install](/docs/getting-started/install/)).

The outputs below come from real runs on macOS. Your ids, keys, hashes, signatures and timestamps
will differ. Long values are shortened with `…`.

## Set up

`init()` reads its settings from the environment, so the code stays the same from your laptop to
production:

```sh
mkdir tenbri-demo && cd tenbri-demo
export TENBRI_STREAM=$PWD/audit/support       # where the stream lives
export TENBRI_KEYS=$PWD/keys                  # its signing keys, apart from the stream
export TENBRI_AGENT=agent:support-assistant   # who acts, when the code does not say
```

| Variable | What it sets | Default |
| --- | --- | --- |
| `TENBRI_STREAM` | The stream: a directory, `file://...`, `s3://bucket/prefix` or `r2://bucket/prefix` | none: `init()` fails without it or a `stream` argument |
| `TENBRI_KEYS` | The keys directory, apart from the stream | `~/.config/tenbri/keys` |
| `TENBRI_AGENT` | Who acts when nothing narrower says: `agent:support` | none: a decision with no principal fails |
| `TENBRI_APPROVER` | Who answers the agent frameworks' approval prompts: `person:alice` | none |
| `TENBRI_SCHEMA` | The [action schemas](/docs/examples/schemas-in-ci/) | `./tenbri.toml` when there is one |

Arguments to `init()` win over the variables. The CLI takes the stream as an argument and reads
`TENBRI_KEYS`.

## Record a decision

<Tabs syncKey="lang">
<TabItem label="CLI">

No code: the CLI writes the same entries with `tenbri append`, one JSON entry per call. It uses
its own stream, so start in a fresh directory if you ran the Python or TypeScript tab.

<Steps>

1. **Create a stream.**

   ```sh
   tenbri init audit/support
   ```

   ```text
   created stream tnb1:13410a435d5a70cc7f96ae05209410bb at audit/support
   stream key fingerprint (pin it): sha256:13410a435d5a70cc7f96ae05209410bb37cd301124e0719229b3184530789b61
   keys: /…/tenbri-demo/keys/tnb1-13410a435d5a70cc7f96ae05209410bb
   verify with: tenbri verify audit/support --key sha256:13410a435d5a70cc7f96ae05209410bb37cd301124e0719229b3184530789b61
   ```

   The directory must be new or empty. Copy the fingerprint somewhere the operator of the stream
   cannot change it: it is your trust root.

2. **Record an intent.**

   `tenbri append` reads one entry as JSON on stdin. An intent is written before the action runs:

   ```sh
   tenbri append audit/support <<'EOF'
   {"kind":"decision","phase":"intent","source":"sdk",
    "principal":{"kind":"agent","id":"support-assistant"},
    "action":{"type":"refund","target":"order:8812"},
    "inputs":[{"ref":"policy:refund","version":"14",
               "digest":"hmac-sha256:9f2c41aa9f2c41aa9f2c41aa9f2c41aa9f2c41aa9f2c41aa9f2c41aa9f2c41aa"}],
    "rule":{"ref":"refund.max_amount","version":"14","result":"allow"}}
   EOF
   ```

   It prints the entry as stored, in canonical form (one line, keys sorted):

   ```json
   {"action":{"target":"order:8812","type":"refund"},"id":"01M5CWCEYW1GZWQE795VT6BGKE","inputs":[{"digest":"hmac-sha256:9f2c41aa…","ref":"policy:refund","version":"14"}],"kind":"decision","phase":"intent","prev":"sha256:b44fbc6c…","principal":{"id":"support-assistant","kind":"agent"},"rule":{"ref":"refund.max_amount","result":"allow","version":"14"},"seq":3,"sig":"ed25519:6258835f…","signer":"sess:2026-10-20:c4de0a227bf3","source":"sdk","stream":"tnb1:13410a435d5a70cc7f96ae05209410bb","ts":"2026-10-20T14:45:26.108Z","v":1}
   ```

   The writer fills in `v`, `id`, `stream`, `seq`, `ts`, `prev`, `signer` and `sig`. You may
   give `id` and `ts` yourself; giving the others is an error:

   ```text
   tenbri: stdin: invalid_field: `seq` is filled in by the writer
   ```

   Note the entry's `id`. The outcome names it.

3. **Record its outcome.**

   ```sh
   tenbri append audit/support <<'EOF'
   {"kind":"decision","phase":"outcome","source":"sdk",
    "intent":"01M5CWCEYW1GZWQE795VT6BGKE","status":"ok",
    "principal":{"kind":"agent","id":"support-assistant"},
    "action":{"type":"refund","target":"order:8812"}}
   EOF
   ```

   ```json
   {"action":{"target":"order:8812","type":"refund"},"id":"01M5CWCF057ED20JDR0QJQ2ZR6","intent":"01M5CWCEYW1GZWQE795VT6BGKE","kind":"decision","phase":"outcome","prev":"sha256:465624fb…","principal":{"id":"support-assistant","kind":"agent"},"seq":4,"sig":"ed25519:d3240344…","signer":"sess:2026-10-20:c4de0a227bf3","source":"sdk","status":"ok","stream":"tnb1:13410a435d5a70cc7f96ae05209410bb","ts":"2026-10-20T14:45:26.149Z","v":1}
   ```

   An intent takes exactly one outcome. A second one for the same intent fails, writes nothing
   and exits 2:

   ```text
   tenbri: entry rejected: bad_intent: no open intent 01M5CWCEYW1GZWQE795VT6BGKE
   ```

4. **Verify against the pinned key.**

   ```sh
   tenbri verify audit/support --key sha256:13410a435d5a70cc7f96ae05209410bb37cd301124e0719229b3184530789b61
   ```

   ```text
   verified 4 entries, stream tnb1:13410a435d5a70cc7f96ae05209410bb, pinned to sha256:13410a435d5a70cc7f96ae05209410bb37cd301124e0719229b3184530789b61
   ```

   The exit code is 0. Without `--key`, `verify` can only say the stream agrees with its own
   genesis key, and exits 3:

   ```text
   consistent: 4 entries, stream tnb1:13410a435d5a70cc7f96ae05209410bb
   NOT pinned: this only shows the stream agrees with its own genesis key; pass --key <fingerprint>
   ```

5. **Query by input.**

   Find every entry that used version 14 of the refund policy:

   ```sh
   tenbri query audit/support --input policy:refund@14 --key sha256:13410a43…
   ```

   ```json
   {"verification":"verified","entry":{"action":{"target":"order:8812","type":"refund"},"id":"01M5CWCEYW1GZWQE795VT6BGKE",…,"phase":"intent",…,"seq":3,…},"seq":3,"hash":"sha256:465624fb…","as_of":{"stream":"tnb1:13410a435d5a70cc7f96ae05209410bb","seq":4,"hash":"sha256:467d3d96…"}}
   ```

   Each line is one match: the entry, its `verification` (`verified` with `--key`, `unpinned`
   without), its hash, and `as_of`, the head of the stream the answer was read from. `--action
   refund` selects by action type and matches both entries. Repeat `--input` to require several.

6. **Tail the stream.**

   ```sh
   tenbri tail audit/support -n 2 --no-follow
   ```

   ```json
   {"action":{"target":"order:8812","type":"refund"},"id":"01M5CWCEYW1GZWQE795VT6BGKE",…,"phase":"intent",…,"seq":3,…}
   {"action":{"target":"order:8812","type":"refund"},"id":"01M5CWCF057ED20JDR0QJQ2ZR6","intent":"01M5CWCEYW1GZWQE795VT6BGKE",…,"phase":"outcome",…,"seq":4,…}
   ```

   Without `--no-follow`, `tail` keeps running and prints new entries as they are written.

</Steps>

</TabItem>
<TabItem label="Python">

Needs `pip install --pre tenbri` (Python 3.10 or later).

```python title="quickstart.py"
import tenbri

log = tenbri.init()  # the stream, its keys and the agent come from TENBRI_*
print("pin this:", log.fingerprint)


@tenbri.decision("issue_refund", target="stripe:{charge}", policy="policy:refund@14")
def refund(charge: str, amount: int) -> str:
    if amount > 500:
        raise tenbri.Refused("over the 500 EUR ceiling")  # recorded as refused
    if amount <= 0:
        raise ValueError("nothing to refund")  # recorded as error, and raised
    return "re_123"  # call the payment API here


print("ok:", refund("ch_3PqX", 20))

try:
    refund("ch_9ZzY", 900)
except tenbri.Refused as e:
    print("refused:", e)

try:
    refund("ch_0", 0)
except ValueError as e:
    print("error:", e)
```

```sh
python quickstart.py
```

```text
pin this: sha256:18c44ddcc1b123d311e4d2e76eac7b007d67cbfe282b5303245aa144e1f94edc
ok: re_123
refused: over the 500 EUR ceiling
error: nothing to refund
```

- `init()` creates the stream and its keys the first time, opens it after that, and flushes and
  closes it at exit. `with tenbri.init(...):` scopes it to a block.
- The intent is durable before `refund` runs. If it cannot be written, `refund` does not run
  (fail closed), unless `init(fail_open=True)`.
- `target` is a template of the arguments: `stripe:{charge}` becomes `stripe:ch_3PqX`. `policy`
  (`ref@version`) is recorded as the rule that allowed the action.
- Who acts: `principal=` on the decorator, else the innermost `with tenbri.agent("agent:billing"):`,
  else `TENBRI_AGENT`. With none, the call raises: Tenbri never guesses.
- `async def` functions work the same way; a cancelled call records `unknown`.

</TabItem>
<TabItem label="TypeScript">

Needs `npm install tenbri@next` (Node 20 or later). Node 22.18 and later run TypeScript files
directly; on Node 20, run `npx tsx quickstart.ts`.

```sh
npm pkg set type=module
```

```ts title="quickstart.ts"
import { Refused, decision, init } from 'tenbri'

const log = await init() // the stream, its keys and the agent come from TENBRI_*
console.log('pin this:', log.fingerprint)

const refund = decision(
  { action: 'issue_refund', target: 'stripe:{charge}', policy: 'policy:refund@14' },
  async ({ charge, amount }: { charge: string; amount: number }) => {
    if (amount > 500) throw new Refused('over the 500 EUR ceiling') // recorded as refused
    if (amount <= 0) throw new RangeError('nothing to refund') // recorded as error, and rethrown
    return 're_123' // call the payment API here
  },
)

console.log('ok:', await refund({ charge: 'ch_3PqX', amount: 20 }))

try {
  await refund({ charge: 'ch_9ZzY', amount: 900 })
} catch (e) {
  if (!(e instanceof Refused)) throw e
  console.log('refused:', e.message)
}

try {
  await refund({ charge: 'ch_0', amount: 0 })
} catch (e) {
  if (!(e instanceof RangeError)) throw e
  console.log('error:', e.message)
}
```

```sh
node quickstart.ts
```

```text
pin this: sha256:a8d69820434ab0a5f1b02798a45b75c22e5f34d190b23d28709c907e82fe4bb7
ok: re_123
refused: over the 500 EUR ceiling
error: nothing to refund
```

- `init()` creates the stream and its keys the first time, opens it after that, and flushes and
  closes it before the process exits. Awaiting it is optional: a decision waits for it.
  `await using log = await init(...)` scopes it to a block.
- The intent is durable before the function runs. If it cannot be written, the function does not
  run (fail closed), unless `init({ failOpen: true })`.
- `target` is a template of the arguments: `stripe:{charge}` reads the first argument's `charge`,
  `{1}` is the second argument. `policy` (`ref@version`) is recorded as the rule that allowed the
  action.
- Who acts: `principal` in the options, else the innermost `agent('agent:billing', () => ...)`,
  else `TENBRI_AGENT`. With none, the call rejects: Tenbri never guesses.
- An `AbortError` records `unknown`.

</Tabs>

## Check it from the CLI

Whichever way you wrote the stream, the CLI reads it. Each call is two entries, its intent and its
outcome:

```sh
tenbri tail audit/support -n 6 --no-follow | jq -c '{seq, phase, status, action: .action.type, target: .action.target, rule: .rule.ref}'
```

```text
{"seq":3,"phase":"intent","status":null,"action":"issue_refund","target":"stripe:ch_3PqX","rule":"policy:refund"}
{"seq":4,"phase":"outcome","status":"ok","action":"issue_refund","target":"stripe:ch_3PqX","rule":null}
{"seq":5,"phase":"intent","status":null,"action":"issue_refund","target":"stripe:ch_9ZzY","rule":"policy:refund"}
{"seq":6,"phase":"outcome","status":"refused","action":"issue_refund","target":"stripe:ch_9ZzY","rule":null}
{"seq":7,"phase":"intent","status":null,"action":"issue_refund","target":"stripe:ch_0","rule":"policy:refund"}
{"seq":8,"phase":"outcome","status":"error","action":"issue_refund","target":"stripe:ch_0","rule":null}
```

Without `--no-follow`, `tail` keeps running and prints new entries as they are written. Verify the
stream against the fingerprint the program printed:

```sh
tenbri verify audit/support --key sha256:18c44ddcc1b123d311e4d2e76eac7b007d67cbfe282b5303245aa144e1f94edc
```

```text
verified 8 entries, stream tnb1:18c44ddcc1b123d311e4d2e76eac7b00, pinned to sha256:18c44ddcc1b123d311e4d2e76eac7b007d67cbfe282b5303245aa144e1f94edc
```

The exit code is 0. Without `--key`, `verify` can only say the stream agrees with its own genesis
key, and exits 3. Find every decision made under version 14 of the refund policy:

```sh
tenbri query audit/support --rule policy:refund@14 --key sha256:18c44ddc…
```

```json
{"verification":"verified","entry":{"action":{"target":"stripe:ch_3PqX","type":"issue_refund"},…,"phase":"intent",…,"rule":{"ref":"policy:refund","result":"allow","version":"14"},"seq":3,…},"seq":3,"hash":"sha256:5b0382d7…","as_of":{"stream":"tnb1:18c44ddcc1b123d311e4d2e76eac7b00","seq":8,"hash":"sha256:27edae77…"}}
```

Seq 1 and 2 are the key entries that creating the stream wrote: the genesis entry (the stream key
certifying itself) and the certification of the session key that signs everything after. The
stream id is `tnb1:` and the first 32 hex digits of the fingerprint.

## Using an agent framework? One more line

With the Claude Agent SDK, the OpenAI Agents SDK or LangGraph, you do not decorate each tool: one
line after `init()` records every tool call, approval and handoff. Install the adapter first
([Adapters](/docs/adapters/)).

<Tabs syncKey="lang">
<TabItem label="Python">

```python
import tenbri

tenbri.init()
tenbri.instrument_claude_agent_sdk()  # pip install --pre tenbri-claude-agent-sdk
tenbri.instrument_openai_agents()     # pip install --pre tenbri-openai-agents
tenbri.instrument_langchain()         # pip install --pre tenbri-langgraph
```

</TabItem>
<TabItem label="TypeScript">

```ts
import { init } from 'tenbri'
import { instrumentClaudeAgentSdk } from '@tenbri/claude-agent-sdk'
import { instrumentOpenAIAgents } from '@tenbri/openai-agents'
import { instrumentLangChain } from '@tenbri/langgraph'

init()
const options = instrumentClaudeAgentSdk({ canUseTool: askAHuman }) // pass to query({ prompt, options })
instrumentOpenAIAgents()
instrumentLangChain()
```

</TabItem>
</Tabs>

Call the one for your framework. Each tool call becomes a decision named after the tool; declare
its target and policy in `tenbri.toml` (`TENBRI_SCHEMA`). Approvals are recorded with the
principal in `TENBRI_APPROVER` as the approver.

## See tampering fail

Change one byte of entry 3 in a copy of the stream, then verify the copy:

```sh
cp -r audit/support tampered
sed -i.bak 's/ch_3PqX/ch_3PqZ/' tampered/batches/000000000003.jsonl
rm tampered/batches/*.bak
tenbri verify tampered --key sha256:18c44ddc…
```

```text
broken at seq 3: bad_signature: the signature does not verify
2 entries verified before it, stream tnb1:18c44ddcc1b123d311e4d2e76eac7b00
```

The exit code is 1. `query` on a stream that does not verify also exits 1. From code, `verify()`
returns a report with `ok` false and the break. In Python, `print(r.ok, r.broken)` after
`r = Tenbri.open("tampered", key=pin).verify()` shows:

```text
False Broken(seq=3, code='bad_signature', message='the signature does not verify')
```

## What is on disk

```text
tenbri-demo/
  audit/support/
    .lock                 held while HEAD is swapped; not part of the stream
    HEAD
    batches/000000000001.jsonl
    ...
    batches/000000000008.jsonl
  keys/tnb1-18c44ddcc1b123d311e4d2e76eac7b00/
    18c44ddcc1b1.json     the stream key's public description
    18c44ddcc1b1.secret   its secret (0600)
    2b0103922caa.json     the session key's public description
    2b0103922caa.secret
```

`HEAD` names the latest entry and is signed by the session key. Each call above wrote its own
batch file, because the calls ran one after the other.

<Aside type="tip">
A long-running writer (the Python or Node package, the Rust `Writer`, or `tenbrid`) groups
concurrent entries into one batch, and writes [checkpoints](/docs/concepts/integrity/#checkpoints).
</Aside>
