Two lines record what every agent of the
[OpenAI Agents SDK](https://openai.github.io/openai-agents-python/) does in a Tenbri stream:
`tenbri.init()` opens the stream, `tenbri.instrument_openai_agents()` (`instrumentOpenAIAgents()`
in TypeScript) hooks every run. Each tool call becomes an intent that is durable before the tool
runs, then its outcome; refused calls, handoffs between agents and the answers a person gives
through `RunState.approve` and `reject` are recorded too. No `hooks=` to pass.

### 2. Instrument your agent

Say what a refund is in `tenbri.toml`, next to your code. The target names the tool's arguments in
braces and is filled from each call; the policy is the rule recorded as having allowed it:

```toml title="tenbri.toml"
[actions.issue_refund]
target = "stripe:{charge}"     # {charge} is filled from the tool call's arguments
policy = "policy:refund@14"    # the rule that allowed it: ref@version
```

Then add the two lines to your agent. Nothing else in it changes:

<Tabs syncKey="lang">
<TabItem label="Python">

```python title="agent.py"
import asyncio

import tenbri
from agents import Agent, Runner, function_tool

tenbri.init()  # reads TENBRI_STREAM... and ./tenbri.toml
tenbri.instrument_openai_agents()  # every run from here on is recorded


@function_tool
def issue_refund(charge: str, amount: int) -> str:
    """Refunds `amount` EUR on the card charge `charge`."""
    return f"refunded {amount} EUR on {charge}"


async def main():
    agent = Agent(name="support", instructions="You handle refunds.", tools=[issue_refund])
    result = await Runner.run(agent, "Refund 20 EUR on ch_1.")
    print(result.final_output)
    print("pin this:", tenbri.default().fingerprint)


asyncio.run(main())
```

Every `Runner.run`, `run_sync` and `run_streamed` from then on is recorded, and every
`RunState.approve` and `reject`. Hooks you pass yourself still run.

</TabItem>
<TabItem label="TypeScript">

```ts title="agent.ts"
import { Agent, run, tool } from '@openai/agents'
import { init } from 'tenbri'
import { instrumentOpenAIAgents } from '@tenbri/openai-agents'
import { z } from 'zod'

const log = await init() // reads TENBRI_STREAM... and ./tenbri.toml
instrumentOpenAIAgents() // every run from here on is recorded

const issueRefund = tool({
  name: 'issue_refund',
  description: 'Refunds `amount` EUR on the card charge `charge`.',
  parameters: z.object({ charge: z.string(), amount: z.number() }),
  execute: async ({ charge, amount }) => `refunded ${amount} EUR on ${charge}`,
})

const agent = new Agent({ name: 'support', instructions: 'You handle refunds.', tools: [issueRefund] })
const result = await run(agent, 'Refund 20 EUR on ch_1.')
console.log(result.finalOutput)
console.log('pin this:', log.fingerprint)
```

Every `run()` and `Runner.run` from then on is recorded, with the agents it hands off to, and every
`RunState` `approve()` and `reject()`. A run that is not streamed returns once its entries are
written.

</TabItem>
</Tabs>

Each tool call is by `agent:<the agent's name>`, here `agent:support`: no `TENBRI_AGENT` needed.

## Configuration

### Environment variables

`tenbri.init()` (`init()`) reads these; an argument (`init(approver=...)`, `init({ approver })`)
wins over its variable.

| Variable | Argument | What it is |
| --- | --- | --- |
| `TENBRI_STREAM` | `stream` | Where entries go: a directory, `file://...`, `s3://bucket/prefix` or `r2://bucket/prefix`. Required. |
| `TENBRI_KEYS` | `keys` | The keys directory, apart from the stream. Default `~/.config/tenbri/keys`. |
| `TENBRI_AGENT` | `agent` | Not used here: each call is by `agent:<the agent's name>`. |
| `TENBRI_APPROVER` | `approver` | Who answers interruptions: `person:alice`. |
| `TENBRI_SCHEMA` | `schema` | The action schemas. Default `./tenbri.toml` when there is one. |
|  | `fail_open` (`failOpen`) | Let tools run, unrecorded and with a warning, when their intent cannot be written. Default: block them. |

`init()` flushes and closes the stream when the process exits. In Python, `with tenbri.init(...) as
log:` scopes it to a block; in TypeScript, `await using log = await init(...)`.

### Map tool calls to actions

A tool call is the action of the tool's name, or of the `[actions.*]` table in `tenbri.toml` that
its name ends with (an MCP tool `mcp__billing__issue_refund` is `issue_refund`). From that table,
the record takes `target`, with each `{argument}` filled from the call's arguments (`{order.id}`
reads a nested field), and `policy`, `"ref@version"`, as the intent's `rule`. In `tenbri.toml`, a
target without placeholders is a pattern for validation only and is not recorded.

`tenbri.toml` is the same file `tenbri schema check` and `tenbrid` validate entries against. A
plain dict (object) in code says the same and wins over the file, per tool name. It can rename the
action, and take functions of the arguments:

<Tabs syncKey="lang">
<TabItem label="Python">

```python
tenbri.instrument_openai_agents(
    actions={
        "issue_refund": {"target": "stripe:{charge}", "policy": "policy:refund@14"},
        "close": {"action": "close_ticket", "target": lambda args: f"ticket:{args['id']}"},
    }
)
```

</TabItem>
<TabItem label="TypeScript">

```ts
instrumentOpenAIAgents({
  actions: {
    issue_refund: { target: 'stripe:{charge}', policy: 'policy:refund@14' },
    close: { action: 'close_ticket', target: (args) => `ticket:${args.id}` },
  },
})
```

</TabItem>
</Tabs>

A tool neither names is recorded under its own name, with no target.

### Options

Python: `tenbri.instrument_openai_agents(**options)`. TypeScript: `instrumentOpenAIAgents({ ... })`.

| Python | TypeScript | Default | What it does |
| --- | --- | --- | --- |
| `actions` | `actions` | `tenbri.toml` | Per tool name: `action`, `target`, `subject` (templates or functions of the arguments) and `policy`. Wins over the file. |
| `approver` | `approver` | `TENBRI_APPROVER` | Who answers an interruption: a principal, or a function of the `ToolApprovalItem` returning one. |
| `tools` | `tools` | every tool (TypeScript: every function tool) | Names to record, or a predicate of the name. |
| `subject` | `subject` | none | The pseudonymous handle of the person the runs are about, for per-subject keys and erasure. |
| `fail_open` | `failOpen` | `init()`'s, `False` | Let actions run, unrecorded and with a warning, when the stream cannot be written. |

In Python, `tenbri_openai_agents.uninstrument()` stops recording the runs started after it
(`uninstrumentOpenAIAgents()` in TypeScript).

## Approvals

The SDK pauses a run when a tool's `needs_approval` (`needsApproval`) says so, and returns the
pending calls as `result.interruptions`. Answer them the SDK's way; each answer is recorded before
the run resumes:

- `state.approve(item)` writes an `approval` entry by the approver **first**. When the run resumes,
  the tool's intent names it: `approval: {by, entry}`.
- `state.reject(item)` writes the call's intent and a `refused` outcome whose `principal` is the
  approver.

Calls the model asked for that never started (a tool input guardrail stopped them) are recorded as
`refused` without a person.

Refunds over 50 EUR need a person; this one approves up to 100 EUR and rejects the rest:

<Tabs syncKey="lang">
<TabItem label="Python">

```python title="refunds.py"
import asyncio
import json

import tenbri
from agents import Agent, Runner, function_tool

tenbri.init()  # TENBRI_STREAM, TENBRI_APPROVER, ./tenbri.toml
tenbri.instrument_openai_agents()


async def over_50(ctx, args, call_id):
    return args["amount"] > 50


@function_tool(needs_approval=over_50)
def issue_refund(charge: str, amount: int) -> str:
    """Refunds `amount` EUR on the card charge `charge`."""
    return f"refunded {amount} EUR on {charge}"


def ask_a_person(item):
    # Your review step: a ticket, a Slack button, a CLI prompt. Here: refunds up to 100 EUR pass.
    return json.loads(item.arguments)["amount"] <= 100


async def main():
    agent = Agent(name="support", instructions="You handle refunds.", tools=[issue_refund])
    result = await Runner.run(agent, "Refund ch_1, ch_2 and ch_3.")
    while result.interruptions:
        state = result.to_state()
        for item in result.interruptions:
            if ask_a_person(item):
                state.approve(item)  # an approval by TENBRI_APPROVER
            else:
                state.reject(item)  # a refused outcome by TENBRI_APPROVER
        result = await Runner.run(agent, state)

    for m in tenbri.default().query(action="issue_refund"):
        e = m.entry
        who = f"{e['principal']['kind']}:{e['principal']['id']}"
        print(e["seq"], e["kind"], e.get("phase", ""), e.get("status", ""), who, e["action"]["target"])


asyncio.run(main())
```

```ts title="refunds.ts"
import { Agent, run, tool, type RunToolApprovalItem } from '@openai/agents'
import { init } from 'tenbri'
import { instrumentOpenAIAgents } from '@tenbri/openai-agents'
import { z } from 'zod'

const log = await init() // TENBRI_STREAM, TENBRI_APPROVER, ./tenbri.toml
instrumentOpenAIAgents()

const issueRefund = tool({
  name: 'issue_refund',
  description: 'Refunds `amount` EUR on the card charge `charge`.',
  parameters: z.object({ charge: z.string(), amount: z.number() }),
  needsApproval: async (_context, { amount }) => amount > 50,
  execute: async ({ charge, amount }) => `refunded ${amount} EUR on ${charge}`,
})

// Your review step: a ticket, a Slack button, a CLI prompt. Here: refunds up to 100 EUR pass.
const askAPerson = (item: RunToolApprovalItem) =>
  item.rawItem.type === 'function_call' && JSON.parse(item.rawItem.arguments).amount <= 100

const agent = new Agent({ name: 'support', instructions: 'You handle refunds.', tools: [issueRefund] })
let result = await run(agent, 'Refund ch_1, ch_2 and ch_3.')
while (result.interruptions.length) {
  for (const item of result.interruptions) {
    if (askAPerson(item)) result.state.approve(item) // an approval by TENBRI_APPROVER
    else result.state.reject(item) // a refused outcome by TENBRI_APPROVER
  }
  result = await run(agent, result.state)
}

for (const { entry: e } of await log.query({ action: 'issue_refund' })) {
  console.log(e.seq, e.kind, e.phase ?? '', e.status ?? '', `${e.principal?.kind}:${e.principal?.id}`, e.action?.target)
}
```

## Choose where entries go

The stream is wherever `TENBRI_STREAM` points; the code does not change.

| Location | `TENBRI_STREAM` | Credentials |
| --- | --- | --- |
| A local directory | `./audit` or `file:///var/lib/audit/support` | none |
| AWS S3, MinIO | `s3://bucket/prefix` | `AWS_ACCESS_KEY_ID`, `AWS_SECRET_ACCESS_KEY`, `AWS_REGION`; `AWS_ENDPOINT_URL` (and `AWS_ALLOW_HTTP=true` for plain HTTP) for MinIO |
| Cloudflare R2 | `r2://bucket/prefix` | `CLOUDFLARE_ACCOUNT_ID`, `AWS_ACCESS_KEY_ID`, `AWS_SECRET_ACCESS_KEY` |

Signing keys stay on the machine that writes; only entries go to the bucket, with
`"durability":"replicated"`. See [Storage](/docs/reference/storage/) for every variable. The
bindings do not write through a `tenbrid` server; to send entries to `tenbrid` over REST, record
by hand as in [any other framework](/docs/adapters/planned/#use-tenbri-from-any-framework-today).

## Test your agent offline

Give the agent a scripted model: a `Model` that returns the next prepared turn. The SDK runs as
usual, with no API key and no network, and you assert on what the stream holds. Give `init()` a
stream and keys in a temporary directory, so tests never touch your real keys:

<Tabs syncKey="lang">
<TabItem label="Python">

```python title="test_agent.py"
import asyncio
import json

import tenbri
from agents import Agent, Runner, function_tool, set_trace_processors
from agents.items import ModelResponse
from agents.models.interface import Model
from agents.usage import Usage
from openai.types.responses import ResponseFunctionToolCall, ResponseOutputMessage, ResponseOutputText

set_trace_processors([])  # no API key: export traces nowhere (entries still carry their ids)


class Scripted(Model):
    """Plays the model's turns from a script: no API key, no network."""

    def __init__(self, *turns):
        self.turns = list(turns)

    async def get_response(self, *args, **kwargs):
        return ModelResponse(output=self.turns.pop(0), usage=Usage(), response_id=None)

    def stream_response(self, *args, **kwargs):
        raise NotImplementedError


def call(name, call_id, **args):
    return ResponseFunctionToolCall(
        id=call_id, call_id=call_id, type="function_call", name=name, arguments=json.dumps(args)
    )


def say(text):
    content = [ResponseOutputText(text=text, type="output_text", annotations=[])]
    return ResponseOutputMessage(id="m", type="message", role="assistant", status="completed", content=content)


@function_tool
def issue_refund(charge: str, amount: int) -> str:
    """Refunds `amount` EUR on the card charge `charge`."""
    return f"refunded {amount} EUR on {charge}"


def test_refund_is_recorded(tmp_path):
    # A stream and keys of its own: the test never touches your real keys directory.
    with tenbri.init(tmp_path / "audit", keys=tmp_path / "keys") as log:
        tenbri.instrument_openai_agents(actions={"issue_refund": {"target": "stripe:{charge}"}})
        model = Scripted([call("issue_refund", "c1", charge="ch_1", amount=20)], [say("Refunded.")])
        agent = Agent(name="support", tools=[issue_refund], model=model)
        asyncio.run(Runner.run(agent, "Refund 20 EUR on ch_1."))

        entries = [m.entry for m in log.query(action="issue_refund")]
        assert [(e["phase"], e.get("status")) for e in entries] == [("intent", None), ("outcome", "ok")]
        assert entries[0]["action"]["target"] == "stripe:ch_1"
        assert entries[0]["principal"] == {"kind": "agent", "id": "support"}
        assert log.verify(log.fingerprint).ok
```

```ts title="agent.test.ts"
import { mkdtempSync } from 'node:fs'
import { tmpdir } from 'node:os'
import { join } from 'node:path'
import { Agent, Usage, run, setTraceProcessors, tool, type AgentOutputItem, type Model } from '@openai/agents'
import { init } from 'tenbri'
import { instrumentOpenAIAgents } from '@tenbri/openai-agents'
import { z } from 'zod'

setTraceProcessors([]) // no API key: export traces nowhere (entries still carry their ids)

/** Plays the model's turns from a script: no API key, no network. */
function scripted(...turns: AgentOutputItem[][]): Model {
  return {
    async getResponse() {
      return { output: turns.shift() ?? [], usage: new Usage(), responseId: undefined }
    },
    getStreamedResponse() {
      throw new Error('not scripted')
    },
  }
}
const call = (name: string, callId: string, args: object): AgentOutputItem => ({
  type: 'function_call', name, callId, arguments: JSON.stringify(args), status: 'completed',
})
const say = (text: string): AgentOutputItem => ({
  type: 'message', role: 'assistant', status: 'completed', content: [{ type: 'output_text', text }],
})

const issueRefund = tool({
  name: 'issue_refund',
  description: 'Refunds `amount` EUR on the card charge `charge`.',
  parameters: z.object({ charge: z.string(), amount: z.number() }),
  execute: async ({ charge, amount }) => `refunded ${amount} EUR on ${charge}`,
})

test('a refund is recorded', async () => {
  // A stream and keys of its own: the test never touches your real keys directory.
  const dir = mkdtempSync(join(tmpdir(), 'audit-'))
  const log = await init({ stream: join(dir, 'audit'), keys: join(dir, 'keys') })
  instrumentOpenAIAgents({ actions: { issue_refund: { target: 'stripe:{charge}' } } })
  const model = scripted([call('issue_refund', 'c1', { charge: 'ch_1', amount: 20 })], [say('Refunded.')])
  await run(new Agent({ name: 'support', tools: [issueRefund], model }), 'Refund 20 EUR on ch_1.')

  const entries = (await log.query({ action: 'issue_refund' })).map((m) => m.entry)
  assert.deepEqual(entries.map((e) => [e.phase, e.status]), [['intent', undefined], ['outcome', 'ok']])
  assert.equal(entries[0].action?.target, 'stripe:ch_1')
  assert.deepEqual(entries[0].principal, { kind: 'agent', id: 'support' })
  assert.ok((await log.verify(log.fingerprint!)).ok)
  await log.close()
})
```

## Troubleshooting

These messages come from real runs; paths are shortened.

| Message | Cause | What to do |
| --- | --- | --- |
| `InvalidRequestError: no stream: pass tenbri.init(stream) or set TENBRI_STREAM to a directory or s3://bucket/prefix` (TypeScript: `pass init({ stream })`) | `init()` found no stream. | Set `TENBRI_STREAM`, or pass the stream to `init()`. |
| `InvalidRequestError: Tenbri is not initialized: call tenbri.init() first` (TypeScript: `call init() first`) | A run started before `init()`. | Call `init()` at startup, before the first run. |
| Python: `UserError: Error running tool issue_refund: read-only: no stream key for tnb1:… in …/keys` | The intent could not be written (here the stream's keys are not in this keys directory), so the run stopped before the tool ran. | Set `TENBRI_KEYS` to the directory the stream was created with. Any write failure surfaces this way: check the `__cause__`. |
| TypeScript: `ToolCallError: Failed to run function tools: NoSessionKeyError: read-only: no stream key for tnb1:… in …/keys` | The same, from the `tenbri` guardrail; `error.error` is the `TenbriError`. | The same. |
| `UserError: Error running tool issue_refund: 'stripe:{charge_id}': no argument 'charge_id'` | The target names an argument the tool does not have. | Match the placeholder to the tool's parameters. |
| `InvalidRequestError: tenbri.toml: actions.issue_refund: policy: expected ref@version` | A `policy` without its version, raised by `init()`. | Write `policy = "policy:refund@14"`. |
| `tenbri: c2 approved, by nobody known: set TENBRI_APPROVER` (a warning) | `state.approve` with no approver configured: no approval entry is written. | Set `TENBRI_APPROVER`, or pass `approver`. |
| `tenbri: not recorded, the action goes ahead (fail_open): …` (`failOpen` in TypeScript) | `fail_open` is on and the stream could not be written; the tool ran. | Fix the stream; the call is not in the record. |
| `ImportError: …: pip install --pre tenbri-openai-agents` | `tenbri.instrument_openai_agents()` without the adapter installed. | Install it. |
| `Error: already recorded by another TenbriRecorder` (TypeScript) | An agent or tool is instrumented twice, by two recorders. | Use one recorder per agent, or build fresh tools for a second one. |
| An MCP tool has no entries (TypeScript) | Tools an agent gets at run time are not instrumented, and only function tools are recorded. | Wrap the call with [`decision()`](/docs/adapters/planned/#use-tenbri-from-any-framework-today). |
| `broken at seq 1: untrusted_root: the genesis key is sha256:e3ed75b1…, not the pinned sha256:0edc8058…` | You verified against another stream's fingerprint (here a stream that was deleted and created again). | Pin the fingerprint printed when this stream was created. |

A process that dies mid-tool leaves its intent open; the next writer of the stream records it as
`unknown`.

## What is written

| What happens | Entry |
| --- | --- |
| A tool call | An `intent` by `agent:<name>`, action and target from the mapping, durable before the tool runs; then the outcome `ok`, or `error` if the tool raised or timed out |
| A tool input guardrail rejects or trips, or `state.reject(item)` | An intent and the outcome `refused` (with the approver as `principal`, for a rejection) |
| A handoff | An intent and an `ok` outcome, action `handoff`, target `agent:<next agent>` |
| `state.approve(item)` | An `approval` entry by the approver; the tool's intent names it in `approval` |
| The run raises (Python) | Open intents end in `error`, or `unknown` when the run was cancelled |

Tool arguments, results and prompts are never written. Entries carry the SDK's trace id (span ids
cut to 16 hex digits; the first 16 still find the span), so a decision and its trace find each
other.

## Advanced: lower-level API

The instrumentation is built on `TenbriRecorder`, on a stream you opened yourself, with no default
stream and no environment. Use it to hold several streams, or to record some runs and not others.
It writes the same entries.

<Tabs syncKey="lang">
<TabItem label="Python">

```python title="recorder.py"
import asyncio

from agents import Agent, Runner, function_tool
from tenbri import AsyncTenbri
from tenbri_openai_agents import TenbriRecorder


@function_tool
def issue_refund(charge: str, amount: int) -> str:
    """Refunds `amount` EUR on the card charge `charge`."""
    return f"refunded {amount} EUR on {charge}"


async def main():
    log = await AsyncTenbri.open("./audit", create=True)
    agent = Agent(name="support", instructions="You handle refunds.", tools=[issue_refund])
    recorder = TenbriRecorder(log, target=lambda tool, args: f"stripe:{args['charge']}")
    async with recorder:  # closes the intents a failed run leaves open
        await Runner.run(agent, "Refund 20 EUR on ch_1.", hooks=recorder, run_config=recorder.run_config())
    print([(m.entry["phase"], m.entry["action"]) for m in await log.query(action="issue_refund")])
    await log.close()


asyncio.run(main())
```

The SDK awaits its run hooks, so the intent is durable before the tool runs. Pass
`run_config=recorder.run_config()`: it is how the recorder hears that a tool raised. Use one
recorder per run, or per conversation when a run resumes after approvals, and answer with
`await recorder.approve(state, item, "person:alice")` or `recorder.reject(...)`.

</TabItem>
<TabItem label="TypeScript">

```ts title="recorder.ts"
import { Agent, run, tool } from '@openai/agents'
import { Tenbri } from 'tenbri'
import { TenbriRecorder } from '@tenbri/openai-agents'
import { z } from 'zod'

const issueRefund = tool({
  name: 'issue_refund',
  description: 'Refunds `amount` EUR on the card charge `charge`.',
  parameters: z.object({ charge: z.string(), amount: z.number() }),
  execute: async ({ charge, amount }) => `refunded ${amount} EUR on ${charge}`,
})

const log = await Tenbri.open('./audit', { create: true })
const recorder = new TenbriRecorder(log, { target: (_tool, args) => `stripe:${args.charge}` })
const agent = recorder.instrument(new Agent({ name: 'support', instructions: 'You handle refunds.', tools: [issueRefund] }))
await run(agent, 'Refund 20 EUR on ch_1.')
await recorder.flush() // outcomes are written in the background
console.log((await log.query({ action: 'issue_refund' })).map((m) => [m.entry.phase, m.entry.action]))
await log.close()
```

The JavaScript SDK does not wait for its run hooks, so `instrument` adds a tool input guardrail
named `tenbri` to each recorded tool, after the tool's own guardrails: the SDK awaits it before the
tool runs. Outcomes and handoffs are written in the background, in order; the next intent and
`flush()` wait for them. Answer with `await recorder.approve(result.state, item, 'person:alice')`
or `recorder.reject(...)`.

</TabItem>
</Tabs>

Both print the intent and the `ok` outcome of `issue_refund` on `stripe:ch_1`. `TenbriRecorder`
takes `tools`, `action`, `target` and `inputs` (functions of the tool name and arguments),
`describe` (any of `action`, `target`, `rule`, `subject` at once), `subject` and `fail_open`
(`failOpen`). `recorder.read(ref, version, content)` (`read(ref, { version, content })`) pins what
the agent read to the next decision, by keyed digest.

<Aside type="note" title="Limits">
In TypeScript, tools added at run time (MCP servers) are not instrumented and only function tools
are recorded. In Python, a streamed run that raises leaves its open intents to the stream's next
writer, which records them as `unknown`.
</Aside>
