`TenbriCallbackHandler` is a LangChain callback handler. Pass it in the `callbacks` of any
[LangGraph](https://langchain-ai.github.io/langgraph/) graph or LangChain agent (`create_agent`,
`createAgent`) and every tool call becomes a decision in a Tenbri stream: an intent that is durable
before the tool runs, then its outcome. When a person answers a `HumanInTheLoopMiddleware`
interrupt, `resume` records the answer as an approval or a refusal.

### 2. Add the handler

<Tabs syncKey="lang">
<TabItem label="Python">

```python title="agent.py"
from langchain.agents import create_agent
from langchain_core.tools import tool
from tenbri import Tenbri
from tenbri_langgraph import TenbriCallbackHandler


@tool
def lookup_order(order: str) -> str:
    """Looks up the shipping status of an order."""
    return f"order {order} shipped"


log = Tenbri.open("./audit", create=True)
tenbri = TenbriCallbackHandler(log, target=lambda tool, args: f"order:{args['order']}")

agent = create_agent("anthropic:claude-sonnet-5-5", tools=[lookup_order], name="support")
result = agent.invoke(
    {"messages": [("user", "Where is order 1042?")]}, {"callbacks": [tenbri]}
)
print(result["messages"][-1].content)
print("pin this:", log.fingerprint)
log.close()
```

The handler is synchronous: open the stream with `Tenbri`, not `AsyncTenbri`.

</TabItem>
<TabItem label="TypeScript">

```ts title="agent.ts"
import { createAgent, tool } from 'langchain'
import { Tenbri } from 'tenbri'
import { TenbriCallbackHandler } from '@tenbri/langgraph'
import { z } from 'zod'

const lookupOrder = tool(async ({ order }) => `order ${order} shipped`, {
  name: 'lookup_order',
  description: 'Looks up the shipping status of an order.',
  schema: z.object({ order: z.string() }),
})

const log = await Tenbri.open('./audit', { create: true })
const tenbri = new TenbriCallbackHandler(log, { target: (_tool, args) => `order:${args.order}` })

const agent = createAgent({ model: 'anthropic:claude-sonnet-5-5', tools: [lookupOrder], name: 'support' })
const result = await agent.invoke(
  { messages: [{ role: 'user', content: 'Where is order 1042?' }] },
  { callbacks: [tenbri] },
)
console.log(result.messages.at(-1)?.content)
console.log('pin this:', log.fingerprint)
await log.close()
```

</TabItem>
</Tabs>

The agent's `name` becomes the principal, `agent:support`. `create=True` makes the stream and its
signing keys the first time. The keys go to `$TENBRI_KEYS`, else `~/.config/tenbri/keys`, never
into the stream. See [keys](/docs/concepts/keys/).

## Configuration

`TenbriCallbackHandler(log, ...)` in Python (keyword arguments),
`new TenbriCallbackHandler(log, { ... })` in TypeScript.

| Python | TypeScript | Default | What it does |
| --- | --- | --- | --- |
| `principal` | `principal` | the agent's name, else `agent:langgraph` | Who acts. The default reads the name given to `create_agent` (`createAgent`). |
| `tools` | `tools` | every tool | Names to record, or a predicate of the tool name. |
| `target` | `target` | none | `(tool, args)` to `action.target`. |
| `inputs` | `inputs` | none | `(tool, args)` to the inputs the call relied on. Python: `{ref, version, digest}` mappings or `(ref, version, content)` tuples. TypeScript: `{ref, version, digest}` or `{ref, version, content}`. Content is digested with the stream's digest key. |
| `fail_open` | `failOpen` | `False` / `false` | Run the tool, unrecorded, when its intent could not be written. A warning is logged. |

When the stream is opened with a digest key (`digest_key` / `digestKey`), each intent also pins the
call's arguments by keyed digest, as the input `langchain:tool_call/<tool call id>@args`. Arguments
and results are never stored.

Pinning the policy a refund relied on, as the repository's example does:

<Tabs syncKey="lang">

```python
    target=lambda tool, args: f"stripe:{args['charge']}",

)
```

</TabItem>

## Approvals and refusals

There are three ways a call can be stopped or approved, and each is recorded:

| What happens | Entries |
| --- | --- |
| A person approves (or edits) a `HumanInTheLoopMiddleware` interrupt, recorded with `resume` | An `approval` by that person; the tool's intent names it in `approval: {by, entry}` |
| A person rejects the interrupt, recorded with `resume` | An intent and a `refused` outcome, with the reviewer in `ext.langchain` |
| Your tool raises `tenbri.Refused` (`throw new Refused(...)`) | The intent, then the outcome `refused` |

`HumanInTheLoopMiddleware` needs a checkpointer. Pass the person's answer through
`tenbri.resume(...)`, which records it and returns the `Command` to invoke the graph with:

<Tabs syncKey="lang">
<TabItem label="Python">

```python title="refunds.py"
from langchain.agents import create_agent
from langchain.agents.middleware import HumanInTheLoopMiddleware
from langchain_core.tools import tool
from langgraph.checkpoint.memory import InMemorySaver
from tenbri import Tenbri
from tenbri_langgraph import TenbriCallbackHandler


@tool
def issue_refund(charge: str, amount: int) -> str:
    """Refund `amount` EUR of a charge."""
    return f"refunded {amount} EUR of {charge}"


log = Tenbri.open("./audit", create=True)
tenbri = TenbriCallbackHandler(log, target=lambda tool, args: f"stripe:{args['charge']}")
agent = create_agent(
    "anthropic:claude-sonnet-5-5",
    tools=[issue_refund],
    name="support",
    middleware=[
        HumanInTheLoopMiddleware(interrupt_on={
            "issue_refund": {
                "allowed_decisions": ["approve", "reject"],
                "when": lambda r: r.tool_call["args"]["amount"] > 50,  # over 50 EUR: ask a person
            }
        })
    ],
    checkpointer=InMemorySaver(),  # interrupts need a checkpointer
)
config = {"callbacks": [tenbri], "configurable": {"thread_id": "ticket-42"}}

agent.invoke({"messages": [("user", "Refund 120 EUR of ch_2")]}, config)  # paused for review
answer = {"decisions": [{"type": "approve"}]}
agent.invoke(tenbri.resume(agent, config, answer, by="person:alice"), config)

agent.invoke({"messages": [("user", "Refund 900 EUR of ch_3")]}, config)  # paused for review
answer = {"decisions": [{"type": "reject", "message": "over the limit"}]}
agent.invoke(tenbri.resume(agent, config, answer, by="person:alice"), config)

for m in log.query(action="issue_refund"):
    e = m.entry
    who = f"{e['principal']['kind']}:{e['principal']['id']}"
    print(e["seq"], e["kind"], e.get("phase", ""), e.get("status", ""), who, e["action"]["target"])
log.close()
```

</TabItem>
<TabItem label="TypeScript">

```ts title="refunds.ts"
import { MemorySaver } from '@langchain/langgraph'
import { createAgent, humanInTheLoopMiddleware, tool } from 'langchain'
import { Tenbri } from 'tenbri'
import { TenbriCallbackHandler } from '@tenbri/langgraph'
import { z } from 'zod'

const issueRefund = tool(async ({ charge, amount }) => `refunded ${amount} EUR of ${charge}`, {
  name: 'issue_refund',
  description: 'Refund `amount` EUR of a charge.',
  schema: z.object({ charge: z.string(), amount: z.number() }),
})

const log = await Tenbri.open('./audit', { create: true })
const tenbri = new TenbriCallbackHandler(log, { target: (_tool, args) => `stripe:${args.charge}` })
const agent = createAgent({
  model: 'anthropic:claude-sonnet-5-5',
  tools: [issueRefund],
  name: 'support',
  middleware: [
    humanInTheLoopMiddleware({
      interruptOn: {
        // over 50 EUR: ask a person
        issue_refund: { allowedDecisions: ['approve', 'reject'], when: (r: any) => r.toolCall.args.amount > 50 },
      },
    }),
  ],
  checkpointer: new MemorySaver(), // interrupts need a checkpointer
})
const config = { callbacks: [tenbri], configurable: { thread_id: 'ticket-42' } }

await agent.invoke({ messages: [{ role: 'user', content: 'Refund 120 EUR of ch_2' }] }, config) // paused for review
let answer: any = { decisions: [{ type: 'approve' }] }
await agent.invoke(await tenbri.resume(agent, config, answer, { by: 'person:alice' }), config)

await agent.invoke({ messages: [{ role: 'user', content: 'Refund 900 EUR of ch_3' }] }, config) // paused for review
answer = { decisions: [{ type: 'reject', message: 'over the limit' }] }
await agent.invoke(await tenbri.resume(agent, config, answer, { by: 'person:alice' }), config)

for (const { entry: e } of await log.query({ action: 'issue_refund' })) {
  console.log(e.seq, e.kind, e.phase ?? '', e.status ?? '', `${e.principal?.kind}:${e.principal?.id}`, e.action?.target)
}
await log.close()
```

</TabItem>
</Tabs>

With a scripted model asking for each refund in turn, both print:

```text
3 approval   person:alice stripe:ch_2
4 decision intent  agent:support stripe:ch_2
5 decision outcome ok agent:support stripe:ch_2
6 decision intent  agent:support stripe:ch_3
7 decision outcome refused agent:support stripe:ch_3
```

The approval (`seq` 3) is written before the intent that names it (`seq` 4). The rejected refund
never ran: its intent and `refused` outcome are written by `resume`.

- `resume` takes what you would pass to `Command(resume=...)`: `{"decisions": [...]}`, a single
  decision, or a mapping of interrupt ids to those when several interrupts are pending. It handles
  both per-call and batched interrupts. A `respond` decision (the person answers instead of the
  tool) is written as a `note`.
- In batched mode, LangChain.js runs none of a batch's calls when one is rejected; their approvals
  stay in the stream, unused.
- For an `interrupt()` of your own, call `tenbri.approve(tool, args, by=..., tool_call_id=...)`
  (TypeScript: `await tenbri.approve(tool, args, { by, toolCallId })`) once the person has answered.
  The call's intent then names that approval.

## Choose where entries go

The stream is wherever `open` points. The handler does not change; only the URL does.

| Location | URL | Credentials |
| --- | --- | --- |
| A local directory | `./audit` or `file:///var/lib/audit/support` | none |
| AWS S3, MinIO | `s3://bucket/prefix` | `AWS_ACCESS_KEY_ID`, `AWS_SECRET_ACCESS_KEY`, `AWS_REGION`; `AWS_ENDPOINT_URL` (and `AWS_ALLOW_HTTP=true` for plain HTTP) for MinIO |
| Cloudflare R2 | `r2://bucket/prefix` | `CLOUDFLARE_ACCOUNT_ID`, `AWS_ACCESS_KEY_ID`, `AWS_SECRET_ACCESS_KEY` |

## Test your agent offline

Give the agent a chat model that plays back prepared messages, tool calls included. The graph runs
as usual, with no API key and no network, and you assert on what the stream holds. The adapter's
own tests work this way.

<Tabs syncKey="lang">
<TabItem label="Python">

```python title="test_agent.py"
import pytest
from langchain.agents import create_agent
from langchain_core.language_models.fake_chat_models import GenericFakeChatModel
from langchain_core.messages import AIMessage
from langchain_core.tools import tool
from tenbri import Refused, Tenbri
from tenbri_langgraph import TenbriCallbackHandler


class FakeModel(GenericFakeChatModel):
    """Plays back AI messages, tool calls included: no API key, no network."""

    def bind_tools(self, tools, **kwargs):
        return self


def calls(*tool_calls):
    return AIMessage("", tool_calls=[{"name": n, "args": a, "id": i} for n, i, a in tool_calls])


@tool
def issue_refund(charge: str, amount: int) -> str:
    """Refund `amount` EUR of a charge."""
    if amount > 500:
        raise Refused("over the refund ceiling")
    return "refunded"


def test_refunds_are_recorded(tmp_path):
    log = Tenbri.open(tmp_path / "audit", keys=tmp_path / "keys", create=True)
    tenbri = TenbriCallbackHandler(log, target=lambda tool, args: f"stripe:{args['charge']}")
    model = FakeModel(messages=iter([
        calls(("issue_refund", "c1", {"charge": "ch_1", "amount": 20})),
        AIMessage("Refunded."),
        calls(("issue_refund", "c2", {"charge": "ch_2", "amount": 900})),
    ]))
    agent = create_agent(model, tools=[issue_refund], name="support")
    config = {"callbacks": [tenbri]}

    agent.invoke({"messages": [("user", "Refund ch_1")]}, config)
    with pytest.raises(Refused):  # ToolNode re-raises what the tool raised
        agent.invoke({"messages": [("user", "Refund ch_2")]}, config)

    entries = [m.entry for m in log.query(action="issue_refund")]
    assert [(e["phase"], e.get("status"), e["action"]["target"]) for e in entries] == [
        ("intent", None, "stripe:ch_1"),
        ("outcome", "ok", "stripe:ch_1"),
        ("intent", None, "stripe:ch_2"),
        ("outcome", "refused", "stripe:ch_2"),
    ]
    assert log.verify(log.fingerprint).ok
    log.close()
```

```sh
python -m pytest -q test_agent.py
```

```ts title="agent.test.ts"
import { test } from 'node:test'
import assert from 'node:assert/strict'
import { mkdtempSync } from 'node:fs'
import { tmpdir } from 'node:os'
import { join } from 'node:path'
import { BaseChatModel } from '@langchain/core/language_models/chat_models'
import { AIMessage } from '@langchain/core/messages'
import type { ChatResult } from '@langchain/core/outputs'
import { createAgent, tool } from 'langchain'
import { Refused, Tenbri } from 'tenbri'
import { TenbriCallbackHandler } from '@tenbri/langgraph'
import { z } from 'zod'

/** Plays back AI messages, tool calls included: no API key, no network. */
class Scripted extends BaseChatModel {
  turns: AIMessage[]
  constructor(turns: AIMessage[]) {
    super({})
    this.turns = turns
  }
  _llmType() {
    return 'scripted'
  }
  bindTools() {
    return this as any
  }
  async _generate(): Promise<ChatResult> {
    const message = this.turns.shift() ?? new AIMessage('done')
    return { generations: [{ message, text: '' }] }
  }
}
const refund = (id: string, charge: string, amount: number) =>
  new AIMessage({ content: '', tool_calls: [{ id, name: 'issue_refund', args: { charge, amount }, type: 'tool_call' }] })

const issueRefund = tool(
  async ({ charge, amount }) => {
    if (amount > 500) throw new Refused('over the refund ceiling')
    return `refunded ${amount} EUR of ${charge}`
  },
  { name: 'issue_refund', description: 'Refund `amount` EUR of a charge.', schema: z.object({ charge: z.string(), amount: z.number() }) },
)

test('refunds are recorded', async () => {
  const dir = mkdtempSync(join(tmpdir(), 'audit-'))
  const log = await Tenbri.open(join(dir, 'audit'), { keys: join(dir, 'keys'), create: true })
  const tenbri = new TenbriCallbackHandler(log, { target: (_tool, args) => `stripe:${args.charge}` })
  const model = new Scripted([refund('c1', 'ch_1', 20), new AIMessage('Refunded.'), refund('c2', 'ch_2', 900)])
  const agent = createAgent({ model, tools: [issueRefund], name: 'support' })
  const config = { callbacks: [tenbri] }
```

The two tests show a difference between the frameworks: Python's `ToolNode` re-raises a tool's
exception (unless you set `handle_tool_errors`), so `invoke` raises `Refused`. LangChain.js hands
the error to the model as a tool message, and `invoke` returns. Both record `refused`.

## Troubleshooting

| Message | Cause | What to do |
| --- | --- | --- |
| Python: `StoreUnavailableError: closed` raised by `invoke`, after LangChain logs `Error in TenbriCallbackHandler.on_tool_start callback: StoreUnavailableError('closed')` | The intent could not be written (here the stream was closed), so the tool did not run. | Keep the stream open for the whole run. Any write failure surfaces this way. |
| TypeScript: LangChain logs `Error in handler TenbriCallbackHandler, handleToolStart: StoreUnavailableError: closed`, and the model gets the tool message `StoreUnavailableError: closed` | The same; `createAgent` hands the error to the model instead of throwing. The tool did not run. | The same. |
| `tenbri: lookup_order ran unrecorded (fail-open): closed` (a warning) | `fail_open` is on and the intent could not be written; the tool ran. | Fix the stream; the call is not in the record. |
| `several interrupts are pending: key the answers by interrupt id` | `resume` got one answer while several interrupts wait. | Pass a mapping of interrupt ids to answers. |
| Entries say `agent:langgraph` | The agent has no name and no `principal` was given. | Pass `name=` to `create_agent` (`name` to `createAgent`), or `principal`. |
| The intent has no `inputs` | The stream was opened without a digest key. | Open it with `digest_key` (`digestKey`) to pin each call's arguments by keyed digest. |
| `tenbri.errors.NotFoundError: no stream at ./audit: ./audit is not a directory` | `open` without `create` on a path with no stream. | Pass `create=True` (`create: true`) the first time, or fix the path. |

An outcome that cannot be written is logged (`tenbri: outcome of … not recorded: …`), not raised:
the tool already ran. A process that dies mid-call leaves its intent open; the next writer of the
stream records it as `unknown`. A LangGraph `interrupt()` inside a tool ends that call as
`unknown`: the tool runs again from the start on resume, as a new decision.

## What is written

| What happens | Entry |
| --- | --- |
| A tool starts | An `intent`: `principal` the agent, `action.type` the tool name, `action.target` from `target`, `ext.langchain` with the run id, tool call id and thread id. Durable before the tool runs. |
| The tool returns | The outcome `ok` (`error` if it returned an error `ToolMessage`, from `handle_tool_error`) |
| The tool raises | The outcome `error`, `refused` for `tenbri.Refused`, `unknown` for a LangGraph interrupt |
| `resume` with `approve` or `edit` | An `approval` by the reviewer; the call's intent names it |
| `resume` with `reject` | An intent and a `refused` outcome; `ext.langchain` holds `decision` and `reviewer` |
| `resume` with `respond` | A `note` by the reviewer |

<Aside type="note" title="Fail closed">
The handler raises its errors (`raise_error` in Python, `raiseError` in TypeScript), and LangChain
awaits it before the tool runs. If the intent cannot be written, the tool does not run. Use
`fail_open` / `failOpen` only if running unrecorded is acceptable.
</Aside>
