`TenbriHooks` plugs into the [Claude Agent SDK](https://code.claude.com/docs/en/agent-sdk). It adds
its hooks next to yours and wraps your `can_use_tool` (`canUseTool`) callback, so every tool call
your agent makes becomes a decision in a Tenbri stream: an intent that is durable before the tool
runs, then its outcome. One line at agent setup, in Python or TypeScript.

### 2. Add the hooks

Open a stream, then pass your options through `instrument`:

<Tabs syncKey="lang">
<TabItem label="Python">

```python title="agent.py"
import asyncio
from claude_agent_sdk import ClaudeAgentOptions, query
from tenbri import AsyncTenbri
from tenbri_claude_agent_sdk import TenbriHooks


async def main():
    log = await AsyncTenbri.open("./audit", create=True)
    options = TenbriHooks(log, "agent:docs").instrument(
        ClaudeAgentOptions(allowed_tools=["Read"])
    )
    async for message in query(prompt="Summarize README.md", options=options):
        print(type(message).__name__)
    print("pin this:", log.fingerprint)
    await log.close()


asyncio.run(main())
```

</TabItem>


## Configuration

`TenbriHooks(log, principal, ...)` in Python (options are keyword arguments),
`new TenbriHooks(log, { principal, ... })` in TypeScript.

| Python | TypeScript | Default | What it does |
| --- | --- | --- | --- |
| `principal` | `principal` | required | The agent, for example `"agent:support"`. |
| `tools` | `tools` | every tool | Names to record, or a predicate of the tool name. Other tools run unrecorded. |
| `describe` | `describe` | `default_describe` / `defaultDescribe` | `(tool, input)` to the intent's fields: `target`, `inputs` (each `{ref, version, digest}`), `rule`, `subject`, or `action` to rename the action. Return `None` / `undefined` for no extra fields. The default records only the target of file and web tools (`file_path`, `notebook_path`, `path`, `url`). |
| `approver` | `approver` | none | Who approves through `can_use_tool`: a principal such as `"person:alice"`, or a function of the call returning one. Leave it unset when your own code decides and no person approves. |
| `fail_open` | `failOpen` | `False` / `false` | Let a tool run, unrecorded, when its intent could not be written. A warning is logged. |
| `timeout` | `timeout` | `2.0` seconds / `2000` ms | How long the intent (or approval) may take to become durable before the tool is denied (or runs, with `fail_open`). |

Methods and exports:

- `instrument(options)` returns your options with Tenbri's hooks appended to yours (`PreToolUse`,
  `PostToolUse`, `PostToolUseFailure`, `PermissionDenied`) and your `can_use_tool` wrapped.
- `hooks.can_use_tool(fn)` (`hooks.canUseTool(fn)`) wraps a permission callback on its own, if you
  build options another way.
- `entry_hash(entry)` (`entryHash`) is the hash an `approval` member names.

A `describe` for an MCP tool, renaming the action and recording a target and the rule that allowed
it:

## Approvals

The SDK calls your `can_use_tool` when a tool needs permission. The adapter wraps it and records
what was answered:

| Your callback returns | With an `approver` | Without one |
| --- | --- | --- |
| Allow | An `approval` entry by the approver, for the same action. The tool's outcome names it in `approval: {by, entry}`. | Nothing extra: your code decided, not a person. |
| Deny | The intent's outcome is `refused`. | The same. |

A denial outside `can_use_tool` (a permission rule, auto mode) reaches the `PermissionDenied` hook
and is also `refused`. Tools that never ask get an intent and an outcome, with no approval. If the
approval cannot be written, the tool is denied (unless `fail_open`).

A support agent whose refund tool asks a person first. Keep the streamed prompt: older SDK releases
call `can_use_tool` only with one.

<Tabs syncKey="lang">
<TabItem label="Python">

```python title="refund.py"
import asyncio
import os
from claude_agent_sdk import (
    ClaudeAgentOptions, PermissionResultAllow, PermissionResultDeny,
    create_sdk_mcp_server, query, tool,
)
from tenbri import AsyncTenbri
from tenbri_claude_agent_sdk import TenbriHooks


@tool("issue_refund", "Refund a Stripe charge", {"charge": str, "amount_eur": int})
async def issue_refund(args):
    return {"content": [{"type": "text", "text": f"refunded {args['amount_eur']} EUR"}]}


async def ask(tool, tool_input, ctx):
    # Your permission prompt: a person answers.
    answer = await asyncio.to_thread(input, f"Allow {tool} {tool_input}? [y/N] ")
    return PermissionResultAllow() if answer.lower() == "y" else PermissionResultDeny(message="no")


def describe(tool, tool_input):
    if tool == "mcp__billing__issue_refund":
        return {
            "action": "issue_refund",
            "target": f"stripe:{tool_input['charge']}",
            "rule": {"ref": "policy:refund", "version": "14", "result": "allow"},
        }
    return None


async def prompt():  # can_use_tool needs a streamed prompt
    content = "Ticket 4512: the customer was charged twice (ch_123, 30 EUR). Refund the duplicate."
    yield {"type": "user", "message": {"role": "user", "content": content}}


async def main():
    digest_key = os.environ["TENBRI_DIGEST_KEY"].encode()
    log = await AsyncTenbri.open("./audit", create=True, digest_key=digest_key)
    hooks = TenbriHooks(log, "agent:support", describe=describe, approver="person:alice")
    options = hooks.instrument(ClaudeAgentOptions(
        mcp_servers={"billing": create_sdk_mcp_server("billing", tools=[issue_refund])},
        tools=[],  # no built-in tools: only the refund, which asks first
        can_use_tool=ask,
    ))
    async for message in query(prompt=prompt(), options=options):
        print(type(message).__name__)

    for m in await log.query(action="issue_refund"):
        e = m.entry
        who = f"{e['principal']['kind']}:{e['principal']['id']}"
        print(e["seq"], e["kind"], e.get("phase", ""), e.get("status", ""), who, e.get("approval", {}).get("entry", ""))
    await log.close()


asyncio.run(main())
```

```ts title="refund.ts"
import { createInterface } from 'node:readline/promises'
import { createSdkMcpServer, query, tool, type CanUseTool, type SDKUserMessage } from '@anthropic-ai/claude-agent-sdk'
import { Tenbri } from 'tenbri'
import { TenbriHooks } from '@tenbri/claude-agent-sdk'
import { z } from 'zod'

const billing = createSdkMcpServer({
  name: 'billing',
  tools: [
    tool('issue_refund', 'Refund a Stripe charge', { charge: z.string(), amount_eur: z.number().int() }, async (a) => ({
      content: [{ type: 'text', text: `refunded ${a.amount_eur} EUR` }],
    })),
  ],
})

// Your permission prompt: a person answers.
const ask: CanUseTool = async (name, input) => {
  const rl = createInterface({ input: process.stdin, output: process.stdout })
  const answer = await rl.question(`Allow ${name} ${JSON.stringify(input)}? [y/N] `)
  rl.close()
  return answer.toLowerCase() === 'y' ? { behavior: 'allow', updatedInput: input } : { behavior: 'deny', message: 'no' }
}

// canUseTool needs a streamed prompt
async function* prompt(): AsyncGenerator<SDKUserMessage> {
  const content = 'Ticket 4512: the customer was charged twice (ch_123, 30 EUR). Refund the duplicate.'
  yield { type: 'user', message: { role: 'user', content }, parent_tool_use_id: null, session_id: '' }
}

const log = await Tenbri.open('./audit', { create: true, digestKey: process.env.TENBRI_DIGEST_KEY })
const hooks = new TenbriHooks(log, {
  principal: 'agent:support',
  approver: 'person:alice', // who answers the prompt
  describe: (name, input) =>
    name === 'mcp__billing__issue_refund'
      ? { action: 'issue_refund', target: `stripe:${input.charge}`, rule: { ref: 'policy:refund', version: '14', result: 'allow' } }
      : undefined,
})
const options = hooks.instrument({
  mcpServers: { billing },
  tools: [], // no built-in tools: only the refund, which asks first
  canUseTool: ask,
})
for await (const message of query({ prompt: prompt(), options })) console.log(message.type)

for (const { entry: e } of await log.query({ action: 'issue_refund' })) {
  console.log(e.seq, e.kind, e.phase ?? '', e.status ?? '', `${e.principal?.kind}:${e.principal?.id}`, e.approval ?? '')
}
await log.close()
```

## Choose where entries go

The stream is wherever `open` points. The adapter does not change; only the URL does.

| Location | URL | Credentials |
| --- | --- | --- |
| A local directory | `./audit` or `file:///var/lib/audit/support` | none |
| AWS S3, MinIO | `s3://bucket/prefix` | `AWS_ACCESS_KEY_ID`, `AWS_SECRET_ACCESS_KEY`, `AWS_REGION`; `AWS_ENDPOINT_URL` (and `AWS_ALLOW_HTTP=true` for plain HTTP) for MinIO |
| Cloudflare R2 | `r2://bucket/prefix` | `CLOUDFLARE_ACCOUNT_ID`, `AWS_ACCESS_KEY_ID`, `AWS_SECRET_ACCESS_KEY` |

## Test your agent offline

The adapter's own tests run the real SDK against `testing/fake-claude.mjs`, a stand-in for the
Claude Code CLI: no model, no API key, no cost. Copy it into your tests and point the SDK at it.
It needs Node on the `PATH`.

```sh
curl -fsSLO https://raw.githubusercontent.com/tenbri/tenbri/main/adapters/claude-agent-sdk/testing/fake-claude.mjs
chmod +x fake-claude.mjs
```

`FAKE_CLAUDE_SCENARIO` is a JSON array of the tool calls to play, after the first user message:

| Field | Meaning |
| --- | --- |
| `tool`, `input`, `id` | The tool name, its input, and the tool use id |
| `ask` | `true` to call your `can_use_tool` before running it |
| `result` | `"ok"`, `"error"`, `"interrupt"`, `"denied"` (a permission rule denies it) or `"crash"` (the CLI dies after `PreToolUse`) |

<Tabs syncKey="lang">
<TabItem label="Python">

```python title="test_agent.py"
import asyncio
import json
from pathlib import Path

from claude_agent_sdk import ClaudeAgentOptions, query
from tenbri import AsyncTenbri
from tenbri_claude_agent_sdk import TenbriHooks

FAKE = Path(__file__).parent / "fake-claude.mjs"  # copied from the Tenbri repository


async def run_agent(log, calls):
    """Runs the real SDK against the fake CLI, which plays `calls` as the model's tool calls."""
    options = TenbriHooks(log, "agent:docs").instrument(ClaudeAgentOptions(
        cli_path=str(FAKE),
        env={"FAKE_CLAUDE_SCENARIO": json.dumps(calls)},
    ))
    async for _ in query(prompt="Summarize README.md", options=options):
        pass


def test_each_tool_call_is_recorded(tmp_path):
    async def main():
        log = await AsyncTenbri.open(tmp_path / "audit", keys=tmp_path / "keys", create=True)
        await run_agent(log, [
            {"tool": "Read", "input": {"file_path": "README.md"}, "id": "t1", "result": "ok"},
            {"tool": "Bash", "input": {"command": "make"}, "id": "t2", "result": "error"},
        ])
        entries = [m.entry for m in await log.query(principal="agent:docs")]
        assert [(e["action"]["type"], e["phase"], e.get("status")) for e in entries] == [
            ("Read", "intent", None),
            ("Read", "outcome", "ok"),
            ("Bash", "intent", None),
            ("Bash", "outcome", "error"),
        ]
        assert entries[0]["action"]["target"] == "README.md"
        assert "target" not in entries[2]["action"]  # the command is never stored
        assert (await log.verify(log.fingerprint)).ok
        await log.close()

    asyncio.run(main())
```

## Troubleshooting

When the adapter blocks a tool, the agent receives the reason as the hook's denial, so it shows up
in the model's transcript.

| Message | Cause | What to do |
| --- | --- | --- |
| `Tenbri could not record the intent, so Read is blocked: closed` | The stream was closed before the agent ran. | Keep the stream open for the whole session; close it after `query` finishes. |
| `Tenbri could not record the intent, so Read is blocked: read-only: no stream key for tnb1:… in …/keys` | The stream opened read-only: its keys are not in this keys directory. | Set `TENBRI_KEYS` (or pass `keys=`) to the directory the stream was created with. Check `log.writable`. |
| `Tenbri could not record the intent, so Read is blocked: not durable within 2000 ms` (TypeScript); the same with nothing after the colon (Python) | The write took longer than `timeout`, often a slow bucket. | Raise `timeout`, or move the stream closer to the agent. |
| `Tenbri could not record the approval: …` | The approval entry could not be written, so the allowed tool is denied and recorded `refused`. | Same causes as above. |
| `tenbri: Read runs unrecorded (fail-open): closed` (a warning) | `fail_open` is on and the intent could not be written; the tool ran. | Fix the stream; the call is not in the record. |
| `tenbri.errors.NotFoundError: no stream at ./audit: ./audit is not a directory` | `open` without `create` on a path with no stream. | Pass `create=True` (`create: true`) the first time, or fix the path. |
| `can_use_tool` is never called | The tool was allowed by settings, or (on older SDKs) the prompt was a string. | Pass a streamed prompt, as in [Approvals](#approvals). |
| The intent has no `inputs` | The stream was opened without a digest key. | Open it with `digest_key` (`digestKey`) to pin each tool input by keyed digest. |

If the process dies after `PreToolUse`, no outcome is written. The next writer of the stream
records the open intent as `unknown`. An outcome that cannot be written is logged
(`the ok outcome of … was not recorded`), not retried: the tool already ran.

## What is written

| SDK event | Entry |
| --- | --- |
| `PreToolUse` | An `intent`: `principal` the agent, `action.type` the tool name, `action.target` from `describe`. Durable before the tool runs. |
| `can_use_tool` allows, with an `approver` | An `approval` by that person, for the same action |
| `PostToolUse` | The outcome `ok`, naming the approval if there was one |
| `PostToolUseFailure` | The outcome `error`, or `unknown` when the tool was interrupted |
| `can_use_tool` denies, or `PermissionDenied` | The outcome `refused` |

Nothing of the prompt, the tool input or the tool output is stored. When the stream is opened with a
digest key, the intent pins the tool input by its keyed digest, as an input with `ref`
`claude:tool_input` and the tool use id as its `version`. Whoever holds the input and the key can
prove what the agent sent.
